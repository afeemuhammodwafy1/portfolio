BakiLedger

An offline-first Android app for keeping everyday dues, payments, and balances organized — designed around clarity, speed, privacy, and a deliberately lightweight local experience.

Platform: Android

01 · Overview

Turning an everyday tracking problem into a focused product.

BakiLedger is a lightweight Android ledger built for people who want a clear record of money they owe or are owed without adopting a full accounting system.

The product keeps the core interaction simple: create a shop or person, set an opening balance when needed, record dues and payments, then check the current balance at any time.

02 · The Problem

The hard part was not accounting. It was keeping the record understandable.

Everyday baki is often maintained through memory, notebooks, chat messages, or scattered notes. These methods can work for a while, but they make it harder to answer a basic question quickly: what is the balance right now?

I approached BakiLedger as a small, focused product rather than a complete business accounting suite. That decision kept the experience centered on the user's immediate task instead of adding features that were not necessary for personal tracking.

03 · Product Direction

Clarity first. Speed second. Complexity last.

Clear Balances

The current due stays visible so users do not need to reconstruct the balance from individual transactions.

Fast Recording

Due and payment actions are kept close to the shop or person record to reduce unnecessary navigation.

Private by Design

The app is offline-first, keeping everyday ledger data on the device unless the user chooses to export or back it up.

04 · Interface & Experience

A compact interface built around the balance.

The visual direction uses a restrained Material 3 system with a green accent, generous spacing, clear hierarchy, and lightweight surfaces. The goal was to make the app feel calm and practical rather than like a traditional accounting dashboard.

05 · Core Features

Small set of features, complete everyday workflow.

  • Multiple records: Keep separate balances for different shops or people.
  • Due & payment tracking: Record additions and payments with exact timestamps and optional notes.
  • Opening balance: Start a record from an existing amount without manually recreating old transactions.
  • History & summaries: Review transaction history and see daily changes at a glance.
  • Backup & restore: Export a full JSON backup and restore it later with replace or merge options.
  • Data export: Generate CSV data and shop-wise PDF statements when a shareable record is needed.
06 · Technical Approach

Local-first architecture without unnecessary infrastructure.

BakiLedger uses Kotlin, Jetpack Compose, and Material 3. Instead of introducing a database for this product's scope, application data is stored in a private JSON file inside app storage.

APP UI → ViewModel → Local JSON Store Shop: id · name · phone · address · createdAt Transaction: id · shopId · amount · type · note · timestamp Balance = Opening Balance + Due − Payments

This keeps the application independent of a backend and avoids requiring an internet connection for normal use. Backup and restore are explicit user actions rather than an invisible synchronization layer.

07 · Retrospective

What this project taught me.

BakiLedger expanded my work beyond web development into Android product development, where interaction details and state management become especially important on a small screen.

The project also reinforced a useful product lesson: a smaller feature set can create a stronger experience when every feature supports the primary task. Designing the app around a clear balance, predictable transactions, and user-controlled data kept the product focused from interface to architecture.
